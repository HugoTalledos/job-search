# Revisión y corrección de CV desde Telegram

## Objetivo y alcance

El usuario debe poder detectar y corregir afirmaciones falsas en el CV ajustado antes de recibir el PDF y también corregir un PDF ya entregado. Una corrección factual confirmada, por ejemplo «no hablo inglés», debe modificar el CV actual y seguir vigente en futuros CV y reconstrucciones del perfil. Los cambios de redacción y formato pertenecen solo a la revisión del CV de esa oferta. La corrección de un borrador no debe repetir el ajuste completo con el modelo; el PDF se renderiza desde el Markdown aprobado.

El bot seguirá operando únicamente en el chat privado configurado. Una corrección no registra una postulación; el botón «✅ Apliqué» permanece en los PDF entregados.

## Experiencia en Telegram

1. «📄 Ajustar CV» prepara el encaje y el Markdown del CV, guarda un borrador y envía un resumen de sus secciones clave junto con el Markdown completo como documento de texto. Todavía no renderiza ni entrega el PDF.
2. El mensaje de revisión ofrece «✅ Aprobar y generar PDF», «✏️ Corregir» y «❌ Cancelar». El usuario puede responder al mensaje del borrador con una instrucción concreta; el bot la vincula al identificador de ese borrador. Una respuesta sin borrador identificable no altera datos.
3. El bot propone una revisión con el fragmento anterior y el nuevo. Para datos personales también muestra el cambio que quedará vigente en futuros CV; para redacción y formato indica que solo cambia esta versión. El usuario confirma o rechaza la propuesta. Si la instrucción es ambigua o no puede representarse como corrección factual segura, el bot pide precisión y no guarda cambios.
4. Cada corrección confirmada crea una revisión del Markdown. El bot muestra de nuevo el resumen y permite consultar el texto completo. «Aprobar y generar PDF» solo acepta el identificador de la revisión activa que el usuario vio; botones de revisiones antiguas responden que el borrador cambió.
5. Al aprobar, el PDF se renderiza desde el Markdown exacto de esa revisión y se envía con su resumen y el botón «✅ Apliqué». Para un CV ya entregado, «Corregir CV» en el mensaje del PDF abre un borrador desde el Markdown guardado y termina con una nueva versión; la entrega anterior no se sobrescribe ni se retira.

El bot no promete que una vista resumida baste para detectar todos los errores: el texto completo siempre está disponible antes de aprobar. La aprobación es explícita y está ligada a una revisión inmutable.

## Correcciones factuales y perfil

- Un intérprete convierte la instrucción en una propuesta de operaciones estructuradas sobre hechos del candidato, empezando por idiomas, habilidades y sus niveles, seniority, años de experiencia y afirmaciones verificables del perfil. Los campos que no se pueden identificar sin ambigüedad no se modifican automáticamente. La propuesta también incluye el cambio puntual al Markdown del CV.
- Las correcciones factuales confirmadas se guardan como registros inmutables en `profile_corrections/{id}`, con la afirmación original, la operación estructurada, la fecha y el alcance global. `profile_corrections/current` conserva la versión y el orden de las correcciones activas. Una corrección posterior puede reemplazar o revocar una anterior sin perder el historial. La confirmación del dato es independiente de la aprobación posterior del PDF: si se cancela el borrador, el hecho confirmado sigue vigente.
- El perfil inferido sin correcciones se conserva por separado dentro de `profiles/current`; los documentos existentes se inicializan con su perfil actual como base. El perfil efectivo se obtiene aplicando las correcciones en orden sobre esa base, con prioridad para lo confirmado por el usuario. Así se puede reemplazar o revocar una corrección sin acumular transformaciones sobre un perfil ya corregido.
- Al confirmar una corrección se actualiza la proyección del perfil efectivo en los campos superiores de `profiles/current`, en la misma transacción que la versión de correcciones, para que los lectores actuales de scoring, preferencias y CV vean el mismo resultado. Una ejecución posterior de `/build-profile` guarda la nueva inferencia base y vuelve a aplicar las correcciones antes de publicar el perfil efectivo. Si una corrección afecta palabras clave o cargos objetivo, se recompila el plan de búsqueda con control de versión; un fallo de esa recompilación no elimina la corrección y se informa para reintento.
- Los prompts de construcción del perfil y ajuste del CV reciben las correcciones vigentes como restricciones explícitas. Se valida el borrador contra negaciones y sustituciones inequívocas antes de presentarlo; una salida que contradiga una corrección confirmada se rechaza y no se envía como PDF. La revisión humana sigue siendo necesaria para errores no detectables automáticamente.
- Una corrección factual cambia la huella del perfil efectivo, por lo que las solicitudes futuras crean una versión de CV nueva. El CV que se está revisando conserva su propio historial de borradores. Para el resumen de encaje de ese CV se actualiza el análisis frente al perfil corregido antes de entregar el PDF, sin volver a redactar todo el CV. Las ofertas históricas ya notificadas no se reevalúan automáticamente.
- El archivo `resume/base.md` no se modifica desde el servicio desplegado. La capa de correcciones prevalece también si el CV base contradice un hecho confirmado. El bot comunica cuando una contradicción en el CV base requiere atención, pero no elimina la corrección persistente.

## Estado, almacenamiento y concurrencia

- Se amplía el flujo de `GenerateTailoredCv` para separar preparación del borrador, revisión, aprobación y entrega. Firestore guarda estado, identificador de oferta, huellas de entradas, revisión activa, alcance de cada propuesta, marcas de aprobación y recibos de Telegram. El Markdown de cada revisión se guarda como objeto privado e inmutable en Cloud Storage; el PDF y el informe se crean solo para la revisión aprobada.
- Una transacción de Firestore compara el identificador de revisión esperado al confirmar una corrección o aprobar. Las pulsaciones repetidas son idempotentes y no pueden aprobar una revisión anterior. Solo puede existir una revisión activa por borrador; una nueva solicitud para la misma oferta puede reanudarlo en vez de generar otra vez.
- La escritura del objeto inmutable precede al cambio de puntero en Firestore. Si falla la transacción, el objeto queda sin publicar y puede limpiarse después; ningún borrador activo apunta a contenido incompleto. Una corrección factual y la actualización del perfil efectivo se publican junto con la revisión confirmada. El fallo al guardar cualquiera de esas partes deja la revisión previa activa y permite reintentar.
- Tras aprobar, la generación del PDF y la entrega tienen estados y recibos separados. Si falla el renderizado o Telegram, el borrador aprobado y su Markdown permanecen; reintentar no llama otra vez al modelo para ajustar el CV. El PDF anterior de una oferta entregada permanece disponible como versión histórica.
- Los borradores, respuestas y botones se validan contra el chat y usuario configurados. Los identificadores de callback no contienen texto del CV ni hechos personales. Los registros técnicos no incluyen CV, correcciones, perfil, token de Telegram ni descripción de la oferta.

## Integración y pruebas

El diseño reutiliza `TailoredResume.resume_markdown`, `RequiredPdfRenderer`, el seguimiento de versiones en Firestore y el bucket privado existente. Añade operaciones de lectura/escritura de Markdown a `CvArtifactStore`, persistencia de borradores/revisiones y correcciones factuales, y el manejo de mensajes y botones de revisión en el webhook de Telegram. El resumen visible se deriva de la revisión aprobada y del análisis actualizado; no se reutilizan afirmaciones del encaje previo que contradigan una corrección factual.

Las pruebas deben cubrir: borrador sin PDF antes de aprobar; vista completa disponible; corrección factual de idioma que elimina «B2» del CV actual, perfil efectivo y futuros CV incluso tras `/build-profile`; cambio de estilo limitado a una versión; revisión de PDF ya enviado sin sobrescribirlo; botones antiguos y pulsaciones repetidas; fallo de interpretación, almacenamiento, renderizado y entrega con reintentos seguros; restricción al chat privado; y PDF construido desde el Markdown de la revisión aprobada. Las pruebas de integración verificarán que scoring, plan de búsqueda y generación de CV leen el perfil efectivo corregido.
